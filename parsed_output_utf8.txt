1. Project Overview  
The AlgorySoft platform is a specialized e -commerce solution 
designed to sell pre -built software projects (React, Node.js, etc.) 
along with tiered customization services. The system facilitates the 
sale of "Products" (code templates) and "Services" (customization) 
through a streamlined workflow involving client interactions, 
payment gateways, and an administrative project management 
suite.  
Key Features  
• Client Side: Product browsing, tiered purchasing 
(Basic/Silver/Gold), custom request handling, real -time order 
tracking, and live chat.  
• Admin Side: Product management (CRUD), order lifecycle 
management, request approval workflows, 1 :1 client 
communication, and analytics.  
________________________________________  
2. Theoretical Data Models  
Before diving into the flow, the following data structures define how 
information is stored and processed.  
A. User Schema (Client)  
• id: Unique Iden tifier 
• name, email, password_hash, phone  
• role: "Client" (Default)  
• wishlist: Array of Product IDs  
B. Product Schema  
--- Page 2 ---
• id: Unique Identifier  
• title, description, images[], tech_stack[] (e.g., React, 
MongoDB)  
• live_preview_url: Link to demo  
• pricing_tiers:  
o Basic: { price: 5000, features: ["Static", "Contact Form", 
"Domain"] }  
o Silver: { price: 12000, features: ["Dynamic", "Admin Panel", 
"Auth"] }  
o Gold: { price: 25000, features: ["AWS Deploy", "Payment 
Gateway", "Full Support"] }  
C. Orde r Schema  
• id: Unique Order ID  
• user_id: Reference to Client  
• product_id: Reference to Product  
• selected_tier: "Basic" | "Silver" | "Gold"  
• status: "Pending" | "Processing" | "Deploying" | "Delivered"  
• progress_percentage: 0 -100 
• payment_status: "Pai d" | "Requested"  
• discount_applied: Boolean (2% if immediate pay)  
D. Request Schema (Custom Orders)  
• id: Unique Request ID  
• user_id: Reference to Client  
• requirements_text: String  
• attachments[]: File URLs  
• status: "New" | "Approved" | "Quoted" | "In  Development"  
• admin_notes: String

3.1 Navigation & Discovery  
Pages: Home, Shop, Product Details, Cart, Checkout.  
1. Landing Page: Displays Trending Products, Hot Products, and 
Carousel.  
2. Shop Page: Grid view of products with Filters (Category, Tech 
Stack, Price).  
3. Authentication: Login/Register required for "Wishlist", "My 
Orders", and "Checkout".

2. Detail Page Displays:  
o Images, Description, Tech Stack, Features.

o Pricing Tiers: Cards showing Basic, Silver, Gold prices.  
3. Purchase Decision:  
o Path A (Instant Purchase ): 
o User selects a tier (e.g., Silver).  
o Clicks "Buy Now".  
o Logic Check: If paying immediately

o Payment Gateway opens.

A. Tiered Pricing Logic (The Cards)   
 
• Basic Card (₹5k Range):  
o Static Frontend (HTML/CSS/JS or basic React).  
o Contact Form integration.  
o Basic Domain assistance.  
o No Database/Admin Panel.  
• Silver Card (₹10k+ Range):  
o Dynamic Frontend.  
o Custom Admin Dashboard.  
o Database Integration (MongoDB/Firebase).  
o Authentication System.  
• Gold Card (₹20k+ Range):  
o Full Stack Application.  
o AWS/Cloud Deployment.  
o Payment Gateway Integration.  
o Priority Support.  
B. Communication Integration  
• WhatsApp: Floating button on Client Side for quick support.  
• Gmail/LinkedIn: Footer links.  
• Internal Chat: Socket.io or similar technology for real -time 1 -
to-1 chat between Admin and Client inside the Order Tracking 
page.  
C. Automation Rules  
1. Discoun t Logic: Total Price * 0.98 applied at checkout if 
payment method is "Instant Pay".
